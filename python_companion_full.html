How this guide works

Every lesson takes about two minutes and teaches one idea. You don’t have to read them in order. Use By project to see which lessons to read before each project, or jump straight to the error decoder when something breaks.

1. Read a little

One small idea at a time, in plain words.

2. Predict first

Pick what you think will happen before you see the answer. Guessing is the point.

3. Step through

Watch the code run one line at a time, with the values on screen.

4. Decode errors

Look up an error message and get a plain-English fix.

Every example on this page is real Python that was run and recorded, so what you see is what Python does. You can’t break anything here. Reading is only half the job, though: you learn Python by writing it, so try each idea in VS Code too.

The error decoder

An error message looks scary, but it follows a pattern. Read it from the bottom.

Traceback (most recent call last):
  File "hill.py", line 101, in <module>
    print(knapsack_problem().get_value(result))
  File "knapsack.py", line 24, in check_weight
    weight += self.weights[i]*sack[i]
IndexError: list index out of range
  1. Read the last line first. It names the problem. Here, IndexError means a position that doesn’t exist.
  2. Find the last line that names your own file. The green line says hill.py, line 101. That is your clue, because knapsack.py is code you didn’t write.
  3. Look at that line, and the lines just above it, in your editor.
